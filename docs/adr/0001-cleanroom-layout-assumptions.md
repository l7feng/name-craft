# 0001 — 干净室边界、布局与行为假设

- 日期：2026-11-09
- 状态：已采纳
- 背景：参考 ReNamer 7.2 行为逻辑重写；参考版为商业二进制，无公开源码。
- 决定：
  1. 干净室：只采用随附手册、Settings.ini、History.txt 描述的行为语义与公开示例作测试基准；不复制、反编译、再分发参考版任何代码与资源。
  2. 布局取 Python src-layout（知识库项目 88 布局卡）；依赖方向 gui/cli → session → engine，fs 为唯一 IO 层。
  3. 首期 12 规则与裁剪按人类 2026-11-09 裁决；冲突口径＝默认拦截＋可选 (n) 后缀＋确认式覆盖（覆盖在 S3 实现）。
- 行为假设（手册未明说，按合理默认实现，参考版副本实测后如有出入再修订）：
  - Rearrange exact 模式分隔符序列未完整命中时名字不变。
  - 冲突后缀格式为 ` (n)`（空格＋括号数字），插在扩展名之前，n 从 2 起递增。
  - Serialize 字母进制补零时按 (索引-1) 的 26 进制表示（a=0）；不补零时按手册序列 a..z, ba..bz, ca..zz, baa..。
  - RegEx 替换串同时支持 `$1`/`${1}` 与 Python `\1` 写法（内部统一转 `\g<n>`）。
  - Insert after/before 锚文本取首次出现。
- 后果：假设项在测试中标注 `assumption`，S2/S3 期间可用参考版副本 Analyze 通道消歧；修订走新 ADR。
- 复核时点：S3 验收前。
